# Edit-loop gates

`check-budgets edit-plan` and `edit-collect` select the edit-loop gate without changing the existing performance lanes or ordinary load plans. `edit-loop` evaluates retained reports. Unavailable evidence stays explicit and blocking; a successful plan is not a measurement.

A smoke cell has at least 100 **total** logical edits. The opt-in `--edit-gate-modes` rotates JSON, TOON, compact text, facade-v1 and CLI probes over those edits, with explicit per-record mode and actual counts. At 100 edits the offered population is 20 per mode. The four-editor Poisson schedule, 15-second per-editor mean and JSON edit acknowledgements are retained. Coverage requires actual assigned edits, decoded answers and applicable tool witnesses, not just a planned count.

Immediate reads use the same editor session after the ACK, with no sleep or barrier. The existing file oracle is reused alongside symbol source, file summary, symbol search and text search. Edit plus one-read latency ends at the first symbol-source read response; later readbacks do not extend that interval. Whole-run monotonic wall evidence includes owned preparation, readiness and normal cleanup. Each smoke run has a 15-minute bound; three independent runs of the same build must agree on every blocking row. Nightly runs retain their original offered schedule and cover 1/4/8/16/32 editors, six independent pinned repositories and the admitted large-file row.

Six-repository edit plus one-read p95 is reported as `OBSERVATIONAL`, with a null budget and an explicit unbudgeted reason. No dedicated p95 target is specified for this cell. Its ACK target, universal readback maximum and other blocking rows remain enforced. Missing or duplicate observations remain unavailable.

Compact freshness is the sole qualified unobservable number: its value stays null with a reason, never zero or PASS. It is nonblocking only after actual semantic witnesses for `read.summary`, `search.symbols`, `relations.callers` and `trace.call_chain`, assigned-edit counts and decoding checks pass. Compact `read.source`, `read.editing_context` and `search.text` are unsupported by the producer contract; each requires an explicit format-refusal record and actual decoded JSON fallback proof, with no compact coverage credit. Missing supported operations, missing fallback/refusal proof, stale content or decode failures remain blocking. The other four mode rows require explicit answer-local freshness observations.

The reference workflow is `.github/workflows/edit-loop-gate.yml`. It runs trusted main code on a separately registered `perf-reference-linux` owned runner. It never substitutes a hosted runner for the reference Linux cgroup/8-CPU/16-GB contract. It does not register a runner or enable scheduling. Operators supply reviewed machine-bound configurations through `EDIT_GATE_REFERENCE_SMOKE_CONFIG` and `EDIT_GATE_REFERENCE_NIGHTLY_CONFIG` and explicitly enable the corresponding `EDIT_GATE_REFERENCE_SMOKE_ENABLED` / `EDIT_GATE_REFERENCE_NIGHTLY_ENABLED` variables. Configurations use the existing strict lane schema, reviewed pinned corpus manifests and exact clean candidate/main/release revisions. The nightly large-file manifest must prove the actual target has at least 10,000 admitted lines. Raw per-run JSON, budget tables, failures and owned shutdown receipts are retained as workflow artifacts.

Two manual smoke faults are available: `ack-wait` and `closed-read-gate`. Their separately reviewed configurations are selected through `EDIT_GATE_ACK_SEED_CONFIG` and `EDIT_GATE_CLOSED_SEED_CONFIG`; `edit_gate_seed` must match the requested fault. The workflow builds the candidate with `gortex_edit_gate_seed` only for those fault runs. The load harness verifies the actual executable's build tag before allocating private state and forwards the known seed explicitly to its owned daemon. Ordinary builds compile the hooks out and ordinary private environments strip ambient seed variables. Faults cannot be selected through the ordinary collector, a nightly lane or a paired run.

The ACK seed restores a real three-second wait on the admitted ACK path inside its existing accounting phase. The closed-gate seed takes the real urgent reclaim admission path and records actual pause/hold observations. Neither edits JSON results nor synthesizes counters. A seeded run must actually fail its intended comparator row; local switch tests alone do not satisfy the required failing-workflow evidence links. The workflow retains failed artifacts and does not tolerate a blocking comparator failure.

No reference measurement, three-run stability result or seeded failing-workflow link is implied by installing this source. Those remain explicit acceptance evidence from an admitted run.
